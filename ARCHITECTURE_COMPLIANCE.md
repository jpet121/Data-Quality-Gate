# Architecture audit using the five original references

All five uploaded source files match the exact SHA-256 identities in the development compiler package. Full files were ingested and extracted locally. Relevant sections were reviewed; this does not mean every page was read, every example mandated, or the entire event application independently specified by these books. The files are not redistributed.

| Source and applicable rule | Application mapping | Evidence / disposition |
|---|---|---|
| Architecture Patterns with Python, extracted pp.35,40,85–89: invert dependencies, isolate repositories, atomic use-case changes, test doubles distinct from real infrastructure | Core validation is pure with immutable inputs; SQLite/PostgreSQL adapters contain transactions; dispatch depends on a repository protocol | Dependency-boundary regression, database rollback/concurrency cases, actual SQLite and PostgreSQL runs |
| Clean Architecture, EPUB OEBPS/Text/part0037.xhtml: dependencies point inward, not from policies to outer details | **Repaired:** ConfigSnapshot now lives in the domain model module; core no longer imports the file-I/O matrix loader. Existing matrix/package import paths re-export the same type | Source diff, annotation/type check, import compatibility and boundary regression |
| Clean Architecture, part0018.xhtml: segregate mutability rather than asserting all state can be immutable | Validated records/configuration snapshots are immutable; repositories and external delivery state are deliberately mutable behind explicit boundaries | Six mutation-resistance tests exercise all event records, nested line items and loaded snapshot maps/tuples |
| Design Patterns, extracted pp.43,45: program to interfaces; favor composition over concrete coupling | Structural WorkflowRepository and Sink protocols; adapters supplied to dispatcher; no hierarchy of speculative factories introduced | Mypy checks implementations; integration tests exercise both repositories through the dispatch behavior |
| Fluent Python: immutable container contents need separate scrutiny; hints do not enforce runtime types | Tuples contain frozen Pydantic line items; loader recursively freezes mapping/list data; Pydantic strict validation is exercised separately from annotations | Nested mutation rejection and loader snapshot tests; existing strict-model/property tests |
| Robust Python, EPUB ch02/ch04/ch08/ch12–13: communicate intent with types; Final alone does not freeze objects; protocols support duck typing | Every application callable is annotated, snapshots/models enforce actual immutability, protocol annotations leave backend choice explicit | Mypy clean across nine application modules; AST signature test; runtime immutability tests |

The Pydantic v2 dependency is explicitly required by the Development contract; framework-agnostic examples in reference books do not override that requirement. Fake repositories/sinks discussed in architecture books are useful **test doubles** and are not evidence that an unspecified production integration is implemented. The application's explicitly named local stub remains a scope/completeness discrepancy under D:p_20; no book excerpt is used to waive that direct contract restriction.

The one-file executable is generated from the same modules, preserving responsibility boundaries without requiring physical multi-file deployment. No extra runtime dependency or business rule was introduced for these architectural corrections. No claim is made about the fitness of undisclosed source requirements, production authentication, multi-process delivery recovery or external systems.
